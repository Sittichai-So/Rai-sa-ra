# แผนพัฒนา RPG ของ Rai-sara เทียบกับเอกสารแผน (MD) ต้นฉบับ

เอกสารแผนต้นฉบับออกแบบสำหรับเกม RPG แบบสำรวจโลกเปิดเรียลไทม์ด้วย Phaser 3
บันทึกนี้เทียบทีละหัวข้อว่าตอนนี้ Rai-sara (frontend, repo นี้) และ back-rai-sara
(backend, `C:\Users\Acer\back-rai-sara`) มีอะไรอยู่แล้ว กับอะไรที่ยังต้องสร้างใหม่จริงๆ
เพื่อให้ตัดสินใจขอบเขตงานต่อไปได้ง่ายขึ้น แทนที่จะไล่ทำตามเอกสารทีละบรรทัดโดยไม่รู้ว่าซ้ำของเดิม

## สิ่งที่มีอยู่แล้วและตรงกับหลักการของแผน (ไม่ต้องสร้างใหม่)

- **Server authority** (หัวข้อ 28-29 ในแผน) — `back-rai-sara/src/rpg/RpgRoom.js` คำนวณทอยเต๋า,
  ผลลัพธ์การต่อสู้/เหตุการณ์ และ HP ทั้งหมดที่ฝั่งเซิร์ฟเวอร์ ฝั่ง client (`pages/rpg/_id.vue`)
  แค่แสดงผลตามที่ได้รับผ่าน Socket.IO เท่านั้น ไม่มีการคำนวณค่าความเสียหายที่ฝั่งเครื่องผู้เล่นเลย
- **แยกข้อมูล static ออกจากข้อมูลผู้เล่น** (หัวข้อ 25-26, 56) — `RpgEngine.js` เก็บ state
  ห้อง/ผู้เล่นแยกจาก `Classes.js`, `Board.js`, `Events.js` ที่เป็นนิยามคงที่ และผลการเล่นจบเกม
  ถูกบันทึกแยกไปที่ MongoDB ผ่าน `model/rpgRun.model.js` แล้ว
- **ระบบคลาส 4 คลาสตามแผน (หัวข้อ 14)** — นักรบ/โจร/นักเวท/นักบวช มีอยู่แล้วทั้งฝั่ง UI
  (`utils/rpgClasses.js`) และฝั่งเซิร์ฟเวอร์ (`back-rai-sara/src/rpg/Classes.js`) พร้อมค่า HP/สเตตัสตั้งต้นต่อคลาส
- **การทอยเต๋าเช็คสถิติแบบ D20** (หัวข้อ 15, 33) — `Events.js` ใช้ `check: { stat, dc }`
  ทอยแล้วเทียบกับค่าสถิติผู้เล่น (str/agi/int) เหมือนหลักการ D20 + modifier ในแผนอยู่แล้ว
- **เควสที่มีทางเลือกและผลลัพธ์ต่างกัน** (หัวข้อ 12) — แต่ละ event มีตัวเลือกที่ให้ผลต่างกันจริง
  (ต่อสู้/หลบหนี, ช่วย/เมิน ฯลฯ) ไม่ใช่แค่ "ฆ่ามอนสเตอร์ 10 ตัวรับรางวัล"
- **โซนเป็นบทของเนื้อเรื่อง** (หัวข้อ 4-11 เทียบกับ `utils/rpgZones.js`) — ป่าต้องคำสาป → หุบเขาร้าง
  → ประตูสู่รังมังกร คือโครงสร้าง "บท" แบบเดียวกับที่แผนแนะนำ เพียงแต่เป็นเนื้อเรื่องไทยของตัวเอง
  ไม่ใช่ Eldoria/Ashenbrook ตามตัวอย่างในเอกสาร (ซึ่งถูกต้องแล้ว ควรคงโลก/ชื่อของเราเอง ไม่ก็อปตัวอย่างในแผนตรงๆ)

## ช่องว่างจริงที่ต้องสร้างใหม่ ถ้าจะ "รื้อสถาปัตยกรรม" ตามแผน

- **การเดินสำรวจแบบเรียลไทม์ด้วย Phaser** — ของเดิมคือทอยเต๋าแล้วเลื่อนไปตาม node บนบอร์ด
  (เดินเป็นช่วงๆ ตามเทิร์น) ไม่ใช่เดินอิสระแบบ real-time บนแผนที่ นี่คือส่วนที่ต่างจากแผนมากที่สุด
  ฝั่ง client ทำแล้ว (Phaser scene, tilemap, การชนกำแพง) ฝั่ง server sync ตำแหน่ง x/y ผ่าน socket
  แล้วด้วย และตอนนี้มีจุดเผชิญหน้ามอนสเตอร์แรก (ก็อบลินซุ่มโจมตี) ที่ผูกกับระบบเช็คสถิติ D20 เดิมได้จริง
  แล้ว (ดูหัวข้อ "สถานะปัจจุบัน" ด้านล่าง) — ที่ยังไม่ทำคือทำแบบนี้ให้ครบทุก event ที่มีอยู่ ไม่ใช่แค่จุดเดียว
- **ชุดภาพ tileset 32x32 แบบ top-down จริง** — asset ปัจจุบัน (`assets/images/rpg/*.png`)
  เป็นภาพ isometric ที่ compositing มาเฉพาะสำหรับบอร์ดเกมเดิม (ดู `assets/images/rpg/CREDITS.txt`)
  ใช้กับ tilemap ของ Phaser ไม่ได้ ต้องหาแพ็ก CC0/CC-BY แบบ top-down ใหม่ (Kenney/OpenGameArt
  ตามหัวข้อ 37-40 ของแผน) แล้วบันทึกแหล่งที่มา/สัญญาอนุญาตให้ครบเหมือนที่ทำไว้กับของเดิม
- **Tiled map editor workflow** — ตอนนี้แผนที่ต้นแบบ (`game/maps/villageMap.js`) เขียนเป็น
  โค้ด JS ตรงๆ เพื่อพิสูจน์ว่า Phaser ทำงานได้ก่อน ถ้าจะทำแผนที่จริงหลายแผนควรย้ายไปออกแบบด้วย
  Tiled แล้ว import เป็นไฟล์ `.json` ตามหัวข้อ 19-20 แทน
- **ระบบ inventory/equipment/skill ที่ซับซ้อนขึ้น** — ตอนนี้มีแค่ inventory เป็น list ของไอเทมข้อความ
  (ไม่มี slot อุปกรณ์, ไม่มีสกิลแยกจากคลาส) ตามหัวข้อ 34-35 ของแผนจะต้องขยายทั้ง schema และ UI

  `worldPlayerJoined` / `worldPlayerMoved` / `worldPlayerLeft`) แยกเป็นระบบคนละชุดจาก
  `rpgHandler.js`/`RpgEngine.js` เดิม (เดิมยังทำงานปกติ ไม่ได้แตะ) ฝั่ง client มี
  `game/net/WorldNetwork.js` เป็นตัวเชื่อม เห็นผู้เล่นคนอื่นเป็นสไปรต์สีฟ้าอ่อน+ชื่อกำกับ เดินตามกันแบบ
  เรียลไทม์จริง — **ทดสอบแล้วแบบ end-to-end จริง** ด้วย headless browser 2 ตัวพร้อมกัน ยิง JWT
  ที่เซ็นด้วยกุญแจจริงจาก `.env.local` (ไม่ได้ผ่านการปลอมทั่วไปแบบตอนทดสอบ UI อย่างเดียว) เชื่อมกับ

  ยังไม่ได้ตรวจสอบตำแหน่ง/ความเร็วฝั่งเซิร์ฟเวอร์ (แค่ relay ตำแหน่งที่ client ส่งมา ยังไม่ได้กันโกงตรงนี้)

  พิกัดที่กำหนดไว้ฝั่งเซิร์ฟเวอร์ (`ENCOUNTERS` ใน `rpgWorldHandler.js`) เกมจะล็อกการเดินแล้วโชว์ป๊อปอัพ
  ตัวเลือก (ต่อสู้/หลบหนี) กดเลือกแล้วเซิร์ฟเวอร์ทอย d20 จริงบวกสถิติผู้เล่น (ตอนนี้ทุกคนได้สเตตัสเริ่มต้น
  แบบนักบวชไปก่อน ยังไม่มีหน้าเลือกคลาสในโหมดนี้) เทียบ DC เดิมทุกอย่าง ได้ผลลัพธ์/HP/ไอเทมตามเดิม แล้ว
  ปลดล็อกให้เดินต่อ — **ทดสอบ end-to-end จริงสำเร็จ** ผ่าน headless browser + backend จริง: เห็นป๊อปอัพ
  ขึ้นตรงจุด, กดปุ่มเลือกได้จริง (คลิก DOM จริงผ่าน CDP ไม่ใช่ mock), เซิร์ฟเวอร์ทอยได้ 2 แพ้ DC 9 ลด HP
  8 ตามสูตรเดิมเป๊ะ, กดดำเนินเรื่องต่อแล้วป๊อปอัพปิด ไม่มี console error
- **เพิ่มจุดที่สอง (`lost_pup`) และตัวยืนมอนสเตอร์/NPC ที่มองเห็นได้บนแผนที่แล้ว** — แต่ละจุดมีสไปรต์
  ทินต์สีต่างกัน (เขียว = ก็อบลิน, ฟ้าเทา = ลูกหมาป่า) ลอยตุ๊บๆ เบาๆ ให้ดูมีชีวิต และจะจางหายไปเมื่อ
  เหตุการณ์นั้นถูกใช้ไปแล้ว (`ENCOUNTER_MARKERS` ใน `villageMap.js` + ทั้งสองฝั่งต้องมีพิกัดตรงกัน
  เพราะยังไม่มีการแชร์ข้อมูลระหว่าง repo — ตามแบบเดียวกับที่ `Classes.js` ถูกก็อปไว้ทั้งสองฝั่งอยู่แล้ว)
  ระหว่างแก้ไฟล์รอบนี้เจอ ESLint บล็อกการคอมไพล์ทั้งหน้าเพราะตัวเลขฐาน 16 (`0x4a9c3f`) ต้องเป็นตัวใหญ่
  ตามกฎ `unicorn/number-literal-case` ของโปรเจกต์ (แก้แล้ว) — บทเรียนคือถ้าเจอหน้าเดิมค้าง/พฤติกรรมไม่เปลี่ยน
  ทั้งที่แก้โค้ดแล้ว ให้เช็ก error overlay ของ Nuxt ก่อน อาจไม่ได้รันโค้ดล่าสุดจริงๆ — ทดสอบจุด `lost_pup`
  ด้วยการ "เดินจริง" ผ่าน headless browser ครั้งแรกไม่ติด (เดาระยะเวลากดปุ่มไม่แม่นพอ เดินไปไม่ถึงจุดจริงๆ)
  เลยเปลี่ยนวิธีทดสอบเป็นการเซ็ตพิกัดตัวละครตรงๆ ผ่าน dev console เพื่อยืนยัน logic แยกจากความแม่นยำของ
  การเดิน — ยืนยันว่า logic ถูกต้อง 100% (ทอยได้ 5+สติปัญญา4=9 ผ่าน DC 8 ได้ไอเทม "เครื่องรางป่า" +
  ความว่องไว 1 ตรงตาม `Events.js` ทุกตัวเลข)
- **เลือกคลาสได้ในโหมดเดินอิสระแล้ว** — หน้า `/rpg/world` มีหน้าเลือกคลาส (นักรบ/โจร/นักเวท/นักบวช
  ใช้ข้อมูลเดิมจาก `utils/rpgClasses.js`) ก่อนเข้าเกม ส่ง `classId` ผ่าน `worldJoin` ไปให้ backend
  ใช้ค่าตั้งต้น HP/สถิติของคลาสนั้นจริง (`Classes.js` เดิม ไม่ได้สร้างค่าใหม่) แทนการล็อกเป็นนักบวชทุกคน
  ตัวละครแต่ละคลาสมีสีทินต์ต่างกันด้วย (แดง/เขียว/ฟ้า/ทอง) ทั้งของตัวเองและที่คนอื่นเห็น —
  **ทดสอบ end-to-end ยืนยันแล้วว่าค่าคลาสถูกใช้จริงฝั่งเซิร์ฟเวอร์** ไม่ใช่แค่สีที่เปลี่ยนแบบผิวเผิน:
  เลือกนักรบแล้วไปสู้ก็อบลิน ทอยได้ 8 บวกพลังโจมตี ได้ผลรวม 13 (ตรงกับ str ของนักรบ = 5 ไม่ใช่ 3
  ของนักบวชที่เคยทดสอบก่อนหน้า)
- **เพิ่มเหตุการณ์ทันทีอีก 3 แบบ (treasure/trap/rest)** — เอาโค้ดสุ่มเดิม `rollTreasure()`/`rollTrap()`
  จาก `Events.js` มาใช้ตรงๆ ต่างจาก goblin/pup ตรงที่ไม่ต้องเลือกตัวเลือก (เดินชนแล้วได้ผลทันที ขึ้นเป็น
  ข้อความ toast แทนป๊อปอัพ) — ทดสอบ end-to-end ผ่านทั้ง 3 แบบสำเร็จ ได้ข้อความ/ไอเทม/HP ตรงตามสูตร
- **เปลี่ยนชุดภาพทั้งหมดตามที่ผู้ใช้ทักท้วงว่า "กากมาก"** — ของเดิมผสม Kenney "Roguelike/RPG Pack" กับ
  "Roguelike Characters" (คนละสไตล์กัน ดูแบน) เปลี่ยนมาใช้ตระกูล "Tiny" ของ Kenney ทั้งหมดแทน: **Tiny

  ประตู ประกอบจาก tile เดิมของ Tiny Town) ให้แผนที่ดูเป็นหมู่บ้านจริงขึ้น ไม่ใช่สนามหญ้าเปล่าๆ — ตรวจสอบ

  ยัง**จัดวางผังแบบเดิม** (บ้านหลังเดียวแปะมุมเดียวๆ ต้นไม้กระจายเป็นกลุ่มเล็กๆ กลางสนามหญ้าเปล่าโล่งๆ)

  Maker 2000/2003 ที่ใช้สีชมพูล้วน (255,103,139) แทนความโปร่งใส ต้องแปลงเป็น alpha จริงก่อนตัด (รอบแรกตัดโดยไม่แปลง

  จริงของ `villageMap.js`) เพราะเครื่องมือบล็อกการอ่านคีย์ลับสำหรับสร้าง token ทดสอบ

- **ยกระดับเป็นเกม RPG แนว D&D (DM + เควสต์ + ลูกเต๋าทอยเอง + ต่อสู้)** — ทำตามสเปกที่ผู้ใช้ส่งมา ตรวจโครงสร้างเดิมก่อน
  (ฉาก Phaser 4 โซนที่โค้ดซ้ำกัน, `encounterMixin` ซ้ำใน 4 canvas, server เป็นตัวตัดสินผลใน `rpgWorldHandler.js`) แล้วต่อยอด
  โดยไม่ลบของเดิม ระบบเก่าที่ยังทำงานอยู่ (บอร์ดทอยเต๋าเดิม, กันโกงตำแหน่ง, กระดานผู้นำ, ห้องปาร์ตี้) ไม่ถูกแตะ — ที่ทำจริงและ
  ทดสอบผ่านเบราว์เซอร์จริงแล้ว:
  1. **Collision ใหม่ทั้งระบบ** (`game/systems/collision.js` + `game/data/objectCatalog.js`) — สาเหตุที่เดินทะลุบ้านได้คือกล่องชน
     ของ static body ไม่ตามตำแหน่งภาพหลังเปลี่ยน origin (เลื่อนลงล่างครึ่งความสูงสไปรต์) และเล็กเกินไป แก้โดยสร้างกล่องชนแบบ
     ระบุพิกัดตรงๆ จาก "footprint" ต่อชนิดวัตถุใน catalog (บ้าน/ต้นไม้/รั้ว/หิน/บ่อน้ำ/เต็นท์ ฯลฯ) แยกชนิด solid / decoration /
     trigger / interactable ใช้ร่วมกันทุกโซน (ดันเจี้ยนใช้ tile collision ร่วมกับวัตถุ) ทดสอบเดินเข้าชนจาก 8 ทิศ (รวมเฉียง)
     ทุกชนิดวัตถุในทั้ง 4 โซน: หมู่บ้าน 136 ครั้ง, ป่า 54, หุบเขา 41, ดันเจี้ยน 27 ไม่มีครั้งไหนทะลุ
  2. **ฉากทั้ง 4 โซนใช้คลาสฐานเดียว** `game/scenes/ZoneScene.js` (เดิมโค้ดซ้ำกัน ~90%) + HUD เดียว `WorldHud.vue` ที่เอา overlay
     ซ้ำใน 4 canvas ออก เหลือ `ZoneCanvas.vue` ตัวเดียว (ไฟล์ `*Canvas.vue` เดิมกลายเป็นตัวห่อบางๆ จึงไม่ต้องแก้หน้า page)
  3. **ปุ่ม E + prompt เดียว** (`interaction.js`): เลือกอันที่ใกล้/สำคัญที่สุดเพียงอันเดียว ไม่เด้ง dialogue เองเมื่อเดินเข้าใกล้
  4. **DM Engine** (`dm.js` + `data/dm.js`): สคริปต์แบบ เงื่อนไข → บรรยาย → ตัวเลือก → ผล → เหตุการณ์ต่อไป ไม่ใช่ AI แสดงเฉพาะ
     จังหวะสำคัญ (เปิดเรื่อง, เข้าโซน, ค้นพบ, เหตุการณ์, ผลการทอย, ผลต่อสู้) มีบันทึกย้อนหลังกด L ดูได้
  5. **NPC มี state + บทสนทนาเปลี่ยนตามเควสต์** (`data/npcs.js` + `dialogue.js`): ผู้เฒ่า (รับเควสต์/ถามเพิ่ม/ไว้ก่อน/รอ/รายงานผล/
     เควสต์บทต่อไป), เจ้าของโรงเตี๊ยม (พักฟื้น HP ด้วยเหรียญ), พ่อค้า (ซื้อ-ขาย-สวมอุปกรณ์), หมอสมุนไพร, ชาวบ้าน, กระดานภารกิจ,
     ประตูออกผจญภัย
  6. **Quest System จริง** (`quests.js` + `data/quests.js`): สถานะ QUEST_NOT_STARTED/ACCEPTED/IN_PROGRESS/COMPLETED/FAILED,
     objective อัปเดตจากเหตุการณ์จริงในเกม (เข้าโซน, ผลเหตุการณ์, ฆ่ามอนสเตอร์) ผ่าน World Event bus (`worldEvents.js` มี
     PLAYER_ENTER_AREA / INTERACT_NPC / FIND_TREASURE / TRIGGER_TRAP / ENCOUNTER_ENEMY / COMPLETE_OBJECTIVE /
     RETURN_TO_VILLAGE ตามสเปก) ตอนนี้มีเควสต์หลัก 2 บท ("เสียงกระซิบแห่งป่า" → "เสียงเงียบแห่งหุบเขา") และเควสต์รองบนกระดาน 2
     อัน (ก็อบลินหน้าประตู, ลูกหมาป่าหลงทาง — อันหลังล้มเหลวได้ถ้าเลือกเมินเฉย)
  7. **Game State ถาวร** (`gameState.js`): level/exp/gold/hp/inventory/equipment/quests/worldFlags/npcStates/storyProgress/
     currentMap/log เก็บใน localStorage แยกตามผู้ใช้ ข้ามหน้าโซนได้ (ผลทอย/HP/ความเสียหายยังตัดสินที่ server)
  8. **ทอยเต๋าเองทุกครั้ง** — server ไม่ทอยอัตโนมัติอีกต่อไป: เลือกตัวเลือกที่มีความเสี่ยง → server ส่ง `worldCheckRequest` →
     ผู้เล่นกดปุ่ม/กด E → server ทอยตอนนั้น (`Dice.js` กลาง: Natural 1/20, Critical, modifier, DC) แสดงด้วยลูกเต๋า 3 มิติจริง
     (`Dice3D.vue` ใช้ CSS 3D + quaternion ไม่พึ่งไลบรารีเพิ่ม) รองรับ d4/d6/d8/d10/d12/d20 หมุน-กระเด้ง-หยุดที่หน้าผลลัพธ์ตามที่
     server ทอย แสดง Dice / Modifier / Total / DC / สำเร็จ-ล้มเหลว ตามสเปก และใช้ทอยเฉพาะเรื่องที่ผลไม่แน่นอนและมีความเสี่ยง
     (สังเกต, สืบสวน, หลบกับดัก, งัดหีบ, โจมตี, หนี) ไม่ทอยตอนเดิน คุย หรือเก็บของธรรมดา
  9. **Marker ตรงความหมาย**: treasure = หีบ (ปิด/เปิด), trap = แผ่นหนามที่ยิงหนามเมื่อเหยียบ, rest = กองไฟ/โรงเตี๊ยม,
     มอนสเตอร์ = สไปรต์มอนสเตอร์จริง ไม่ใช้ตัวละครย้อมสีอีก — treasure/rest ต้องกด E เอง (มีคำบรรยายตอนเดินเข้าใกล้ก่อน)
     trap เป็นกลไกที่เหยียบแล้วให้ทอยหลบ
  10. **ต่อสู้แบบเทิร์นจริง** (`Combat.js`): โจมตี/ทักษะประจำคลาส/ใช้ยา/หนี ทอย d20 เทียบ AC ดาเมจพร้อมคริติคอล มอนสเตอร์ตอบโต้
      DM บรรยายผลทุกรอบ รางวัลเป็นเหรียญ/EXP/ของ เปิด Loot UI ให้กดเก็บ
  11. **Random Encounter แบบตั้งค่าได้** (`WorldZones.js` ตัวแปร `RANDOM_ENCOUNTERS`): ต่อโซนกำหนดตารางน้ำหนัก (ป่า: ศัตรู 35 /
      สมบัติ 15 / กับดัก 15 / NPC 10 / เรื่องราว 10 / ไม่มีอะไร 15) ระยะเดินขั้นต่ำ + cooldown + พื้นที่ปลอดภัยรอบจุดเกิด
      หมู่บ้านไม่มีการสุ่ม
  12. **Debug mode** กด F3: เห็นกล่องชน/รัศมี interact/จุด marker และแผงตำแหน่ง แผนที่ เควสต์ objective flags npc state ผลทอยล่าสุด
      ตารางสุ่มเหตุการณ์ และ event ล่าสุด พร้อมปุ่มเพิ่มเหรียญ/รีเซ็ตเซฟ (ใน dev มี `window.__rpg` ให้ตรวจ state)
  13. **DM ต้อนรับกลับทุกครั้งที่เข้าเกมใหม่**: เมื่อเปิดหน้าเกมใหม่ (รีเฟรช, กลับมาจากแชท, เข้าจากแผนที่โลก — ไม่นับการเดินทางระหว่างโซนด้วยประตู/ทางออก
      ในเกม) DM จะบรรยายที่หมู่บ้านอีกครั้งพร้อมสรุปภารกิจปัจจุบันและเป้าหมายถัดไป (สคริปต์ `welcome_back` / `welcome_back_ready` ใน `game/data/dm.js`,
      ตัวแยกว่าเป็นการเข้าใหม่อยู่ใน `worldController.js`) ส่วนบทนำ `prologue` ไม่ถูกทำเครื่องหมายว่าเล่นแล้วอีกต่อไปจนกว่าผู้เล่นจะกดปุ่ม
      "เริ่มต้นการผจญภัย" จึงไม่หายไปถ้าปิดหน้าเว็บกลางบทนำ และเซฟเกมถูกบันทึกทันทีตอนปิด/รีเฟรชหน้า (ก่อนหน้านี้มีช่วง 0.25 วินาทีที่อาจเสียการเปลี่ยนแปลงล่าสุด)
  - ทดสอบจริงผ่านเบราว์เซอร์ (Edge headless + CDP + server ทดสอบแยกที่ไม่แตะฐานข้อมูลจริง): เปิดเรื่อง → คุยผู้เฒ่า → รับเควสต์ →
    เดินออกประตู → ป่า (DM) → ทอยสังเกตรอยเท้า → ต้นกำเนิดเสียง → หีบ → กับดัก → กองไฟ → ต่อสู้หมาป่าเงา → เก็บ loot → กลับ
    หมู่บ้าน → ผู้เฒ่าเปลี่ยนบทสนทนา → รายงานผล/รับรางวัล → รับเควสต์บทถัดไป + ร้านค้า/โรงเตี๊ยม/กระดานภารกิจ/เมนู
    เควสต์-ถุง-บันทึก + หมดสติ/ฟื้น + random encounter ผ่านหมดโดยไม่มี console error

4. ดันเจี้ยนมี 2 ห้อง ยังไม่มีเควสต์ของตัวเองผูกกับบอสโทรลล์ (มีแค่ "พิชิตดันเจี้ยน") ขยายห้องที่ 3 ขึ้นไปได้
5. เอฟเฟกต์เต๋า Natural 20 (ลูกเต๋าสีทอง) / Natural 1 (สีเทาหม่น) ทดสอบระดับ unit ที่ server แล้ว (สัดส่วนถูกต้อง) แต่ยังไม่เคยเห็น
   เกิดจริงบนหน้าจอเพราะเป็นเรื่องดวง
6. ระบบบอร์ดทอยเต๋าเดิม (`/rpg/board`) ถูกปิดชั่วคราวตามที่ผู้ใช้สั่ง เพราะเกิดความสับสนซ้อนทับกับโหมดเดินสำรวจใหม่ — โค้ดยังอยู่ครบ
   ปิดที่ฝั่งหน้าเว็บด้วยค่า `LEGACY_BOARD_ENABLED = false` ใน `utils/rpgFeatures.js` (ซ่อนปุ่ม "โหมดกระดานเดิม" และ middleware `legacyBoard`
   พาทุกหน้า `/rpg/board*` กลับไป `/rpg`) และที่ฝั่ง backend ด้วยตัวแปร `RPG_BOARD_ENABLED` (ค่าเริ่มต้นปิด ตั้งเป็น `1` ถึงจะเปิด socket ของบอร์ดเดิม)
   ต้องรีสตาร์ต backend ครั้งหนึ่งให้ค่านี้มีผล ส่วนกระดานผู้นำและประวัติการเล่นผ่าน REST ยังใช้งานได้ตามเดิม ถ้าจะเปิดกลับให้สลับสองค่านี้
